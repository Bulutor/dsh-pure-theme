# 从其他 Agent 迁移外观到 DeepSeek Harness

这个插件存在的理由：从其他编程 Agent 转过来的人，第一眼会觉得 DSH 的界面“不是我的”。它把别家的配色搬到 DSH 的语义 token 上，一次点击完成。

## 为什么不能 1:1 复制

编辑器类 Agent 的界面是「活动栏 + 侧栏 + 编辑器 + 面板 + 状态栏」，DSH 是「侧栏 + 对话区（含输入区）+ 右栏 + 卡片/浮层」。两套界面的**面积占比**不同，同一个色值搬过来，观感会变。

三条必须调整的地方：

1. **层级**：DSH 的侧栏必须比对话区**深一档**（或浅一档），否则整屏糊成一块。编辑器主题常常侧栏和编辑区同色，直接套用会失去分区感。
2. **纯黑**：DSH 用 0.5px 描边 + 轻阴影表达层次，纯黑（`#000000`）会把描边吃掉。建议画布不低于 `#101010`，或给描边留出 6% 以上亮度差。
3. **强调色面积**：编辑器里的强调色只用于光标和高亮，DSH 的强调色会铺在按钮、选中的 Tab、链接上。原色饱和度过高时（如 `#00FF88`）建议降饱和 15–25%，或改用 `accentText` 保证按钮文字可读。

## 映射表

| 对方界面 | 对应 DSH 角色 |
|---|---|
| 活动栏 / 侧栏 / 文件树底色 | `sidebar` |
| 编辑器背景 / 聊天主区背景 | `canvas` |
| 输入框、命令面板输入框 | `input` |
| 悬浮卡片、结果面板、通知卡 | `surface` |
| 下拉菜单、Tooltip、右键菜单 | `surfaceAlt` |
| 分割线、面板边框 | `border` |
| 正文文字 | `textPrimary` |
| 次要文字、行号、占位符 | `textSecondary` |
| 主按钮、链接、选中项 | `accent` |
| 主按钮上的文字 | `accentText` |

## 自检清单

导入后按这四条看一眼，基本就能判断是否需要微调：

- [ ] 侧栏与对话区能一眼分开（亮度差 ≥ 6%，或描边清晰可见）
- [ ] 正文与背景对比度 ≥ 4.5:1（插件面板会直接提示低于 4.5 的组合）
- [ ] 按钮文字在强调色上可读（对比度 ≥ 3:1）
- [ ] 代码块在对话区里仍然能辨认（代码块用的是 `canvas` 派生色，画布过亮时建议单独用 `tokens` 指定 `--dsw-alias-markdown-code-block`）

## 从 VS Code 主题直接开始

1. 在 VS Code 里 `Developer: Generate Color Theme from Current Settings`，或直接拿主题扩展的 `themes/*.json`；
2. 在 DSH 外观设置里上传该文件——插件会按上表自动映射；
3. 按自检清单微调 1–2 个角色，再点「导出当前外观」保存成 `.dshtheme` 分享。

## 从终端类 Agent 迁移

Claude Code / Codex CLI 这类终端 Agent 只有 16 色 ANSI 调色板，没有“侧栏/画布”概念。建议：

- 背景取 ANSI black / bright black 两档，分别给 `canvas` 和 `sidebar`；
- 前景取 ANSI white，给 `textPrimary`；
- 强调取 ANSI blue/cyan/magenta 中最“品牌”的一个，给 `accent`；
- 其余角色用插件里的同名预设做起点，比从零调更快。
